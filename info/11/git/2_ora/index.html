GitHub 11. évfolyam 2. óra

GitHub alapok – a projekt felkerül a felhőbe

Repository létrehozása GitHubon, klónozás, módosítások mentése és feltöltése.

1. Git és GitHub – mi a különbség?

Git: a saját gépünkön követi a projekt változásait és commitokat készít.

GitHub: online helyet ad a Git repositorynak, így a projekt másik gépről is elérhető és másokkal is megosztható.

Fontos: az add még nem tölt fel semmit GitHubra. Az add kijelöli a változásokat, a commit helyi pillanatképet készít, a push pedig feltölti a commitokat GitHubra.

2. Repository létrehozása GitHubon

  1. Jelentkezz be a GitHubra.
  2. Válaszd a New repository lehetőséget.
  3. Adj nevet a repositorynak.
  4. Válaszd ki, hogy Public vagy Private legyen.
  5. Hozd létre a repositoryt.

Public: bárki láthatja. Private: csak azok férnek hozzá, akiknek engedélyt adsz.

3. A repository klónozása

A GitHubon másold ki a repository HTTPS-címét, majd a terminálban:

git clone https://github.com/felhasznalo/repo.git
cd repo
code .
A git clone letölti a repositoryt, és automatikusan összekapcsolja a helyi példányt a GitHubon lévővel. Ezért most nem használunk git remote add origin parancsot.

Ha a code . nem működik, nyisd meg a klónozott mappát kézzel a Visual Studio Code-ban.

4. Módosítás → add → commit → push

Módosíts egy fájlt a VS Code-ban, majd:

git status
git add .
git commit -m "index.html módosítása"
git push

A folyamat:

MÓDOSÍTÁS
    ↓
git add .
    ↓
git commit -m "..."
    ↓
git push
    ↓
GITHUB

5. Mi történik az első push-nál?

Az első git push során a gép kérheti a GitHub-hitelesítést. Ilyenkor jelentkezz be a GitHub-fiókoddal a megjelenő böngészőablakban, és engedélyezd a hozzáférést.

Sikeres hitelesítés után a push feltölti a commitot. Ugyanazon a gépen a következő push-oknál általában már nem kell újra bejelentkezni.

6. Ellenőrzés GitHubon

Frissítsd a repository oldalát. Meg kell jelennie a módosított fájlnak és a legutóbbi commit üzenetének. A commitok előzményeiben visszanézhetők a projekt korábbi állapotai.

7. Ha többen dolgozunk: pull

Ha más is dolgozik ugyanazon a repositoryn, munka előtt töltsük le a legfrissebb változásokat:

git pull

Ez lesz a közös munka alapja: pull lefelé hozza a változásokat, push felfelé küldi a saját commitjainkat.

Gyakorlat

  1. Hozz létre egy GitHub repositoryt.
  2. Klónozd a gépedre.
  3. Nyisd meg VS Code-ban.
  4. Készíts vagy módosíts egy index.html fájlt.
  5. Add hozzá a változást és készíts értelmes commitot.
  6. Pushold GitHubra.
  7. Ellenőrizd a böngészőben, hogy megjelent-e.
  8. Végezz még egy módosítást, majd készíts újabb commitot és pushold azt is.

8. A négy GitHub-parancs, amit most tudnod kell

ParancsFeladat
git clone ...A repository első letöltése a gépre.
git pullA GitHubon lévő új változások letöltése.
git commit -m "..."Helyi pillanatkép készítése.
git pushA helyi commitok feltöltése GitHubra.
Következő lépés: ugyanazon a repositoryn két ember fog dolgozni. Ebből jutunk el a közös munkához, majd később a push elutasításához és a merge conflict feloldásához.
