11. évfolyam Közlekedési projekt 31. óra

Mobiltelefonos elrendezés

Elkészítjük a közlekedési oldal harmadik nézetét: 34em alatt a navigáció, a kapcsolódó témák és a sűrűbb tartalmak is telefonhoz igazodnak.

Jonas kurzusából feldolgozva:136. videó – Responding to Phones

Az óra célja

  • A harmadik, telefonos töréspont kiválasztása a design hibája alapján.
  • A 34em-es media query elkészítése.
  • A navigáció egyszerű, JavaScript nélküli átrendezése.
  • A táblázat, a gomb, a térközök és a kapcsolódó témák telefonos igazítása.
  • A három nézet ellenőrzése: laptop, tablet és mobiltelefon.
Kezdőcsomag letöltése Megoldás letöltése

1. Kiindulási állapot

A kezdőcsomag a 30. óra kész megoldása. Már működik benne a 75em-es kisebb laptopos és az 59em-es tabletes media query.

Fontos: nem egy konkrét telefon típusához készítünk szabályt. Addig szűkítjük a nézetablakot, amíg a saját tartalmunk elrendezése problémássá válik.

2. Miért 34em?

Körülbelül 550 px környékén a navigáció, a táblázat és a kapcsolódó témák már túl szűkek. A töréspontot em-ben adjuk meg:

544 ÷ 16 = 34

@media (max-width: 34em) {
  /* telefonos felülírások */
}

A 34em a media queryben körülbelül 544 px-nek felel meg.

3. A külső térközök csökkentése

@media (max-width: 34em) {
  .container {
    width: 94%;
    margin: 15px auto;
    row-gap: 30px;
  }

  .main-header {
    padding: 20px;
  }
}

A telefonon kisebb külső margó és kisebb függőleges hézag elegendő, így több hely marad a tartalomnak.

4. Egyszerű mobilnavigáció hamburgerikon nélkül

@media (max-width: 34em) {
  nav a:link,
  nav a:visited {
    display: block;
    margin-right: 0;
    margin-bottom: 10px;
  }
}

A hivatkozások egymás alá kerülnek. Ehhez nem kell hamburgerikon és JavaScript.

5. A címsor és a „Hasznos” gomb

@media (max-width: 34em) {
  h2 {
    font-size: 28px;
  }

  .like-button {
    position: static;
    margin-bottom: 20px;
  }
}

A kisebb főcím könnyebben törik sorokra. A gomb kikerül az abszolút pozícióból, ezért nem tud ráfedni a címre.

6. A táblázat és az oldalsáv igazítása

@media (max-width: 34em) {
  th,
  td {
    padding: 8px 4px;
    font-size: 14px;
  }

  aside {
    padding: 25px 20px;
  }
}

A táblázat cellái kevesebb helyet foglalnak, az oldalsáv belső térköze pedig illeszkedik a keskeny nézethez.

7. Kapcsolódó témák egy oszlopban

@media (max-width: 34em) {
  .related {
    grid-template-columns: 1fr;
    gap: 16px;
  }

  .related-post {
    flex-direction: row;
  }
}

A tabletes három oszlop helyett egyetlen oszlop marad. Egy témán belül az ikon és a szöveg ismét egymás mellé kerül.

8. A három media query együtt

NézetSzélességElrendezés
Nagy képernyő1200 px felettAz alapértelmezett, kéthasábos oldal
Kisebb laptop75em alattKeskenyebb kéthasábos elrendezés
Tablet59em alattEgyoszlopos fő Grid, három kapcsolódó téma
Mobiltelefon34em alattFüggőleges navigáció és egyoszlopos kapcsolódó rész
500 px-en mindhárom media query érvényes. A későbbi 34em-es blokk csak azokat a tulajdonságokat írja felül, amelyeket újra megadunk.

9. DevTools-ellenőrzés

  1. Nyisd meg az oldalt Responsive módban.
  2. Vizsgáld meg 1200, 944, 544, 543, 430 és 360 px szélességen.
  3. Kapcsold be a media queryk megjelenítését, ha a böngésződ támogatja.
  4. Ellenőrizd, hogy nincs vízszintes görgetősáv.
  5. Nézd meg, hogy a navigáció minden hivatkozása olvasható és kattintható marad-e.
  6. DevToolsban keresd meg, mely tulajdonságok érkeznek a 34em-es blokkból.

10. Önálló feladat

  1. A queries.css végén készítsd el a 34em-es media queryt.
  2. Csökkentsd a konténer és a fejléc térközeit.
  3. Rendezd egymás alá a navigáció hivatkozásait.
  4. Akadályozd meg, hogy a „Hasznos” gomb ráfedjen a címre.
  5. Tedd tömörebbé a táblázatot.
  6. Rendezd egy oszlopba a kapcsolódó témákat.
  7. Teszteld az oldalt legalább három telefonszélességen.

11. Ellenőrző kérdések

  1. Miért nem készítettünk automatikusan 600 px-es töréspontot?
  2. Körülbelül hány pixel a 34em?
  3. Miért érvényes 500 px-en a 75em-es és az 59em-es query is?
  4. Miért állítjuk a gomb pozícióját static értékre?
  5. Miért nincs szükség hamburgerikonra ezen az oldalon?
Válaszok
  1. Mert ott még nem hibásodott meg a saját elrendezésünk; a tartalom alapján választunk töréspontot.
  2. Körülbelül 544 px.
  3. Mert 500 mindkét maximumértéknél kisebb.
  4. Így visszakerül a normál dokumentumfolyamba, és nem fed rá a címre.
  5. A kevés hivatkozás egymás alatt is jól használható, így nincs szükség JavaScriptre.

Mit vigyél el ebből az órából?

  • A töréspontot a saját design hibája alapján választjuk ki.
  • Telefonon az összetett elrendezések gyakran egy oszlopra váltanak.
  • A térközöket, betűméreteket és kezelőszerveket is ellenőrizni kell.
  • Egyszerű webhelyen a mobilnavigáció JavaScript nélkül is megoldható.
  • A közlekedési projekt most már nagy képernyőn, tableten és telefonon is használható.
