Térközök és méretezés a gyakorlatban

A dobozmodell teljes gyakorlati alkalmazása: padding, margin, margóösszevonás, width, height és arányos képméretezés.

Esti ismétlés Jonas kurzusából:34–35. videó – Using Margins and Paddings + Adding Dimensions

Az óra célja és előkészületek

  • Belső térköz beállítása és rövidített megadása.
  • Listaelemek közötti margó kialakítása.
  • A böngésző térközeinek visszaállítása és a specifikusság megfigyelése.
  • A dobozmodell ellenőrzése DevTools segítségével.

Folytasd a korábbi magazinoldalt. A külső fejléc kapjon class="main-header" attribútumot; az aside lesz a kapcsolódó bejegyzések doboza. Ha nincs kéznél az oldalad, töltsd le és csomagold ki a kezdőcsomagot: képeket is tartalmaz. A cikk belső fejlécét és fő képét külön fogjuk kijelölni. Nyisd meg az index.html-t Live Serverrel. Az anyag két nagy részből áll; a térközök után következik a méretezés.

1. Padding a fejlécen

Padding = hely a tartalom és a keret között. A háttérszín a padding területét is kitölti, ezért jól látható a változás. A meglévő szabályt egészítsd ki:

.main-header {
  background-color: #f7f7f7;
  padding: 20px;
}
Próbáld ki az 5 px és 40 px értéket, majd állítsd vissza 20 px-re. A fejléc címsorának saját margója miatt a látható távolság nagyobb lehet a paddingnél; ezt hamarosan megvizsgáljuk.

2. Oldalankénti padding és shorthand

Felül és alul maradjon 20 px, bal és jobb oldalon legyen 40 px:

padding-top: 20px;
padding-right: 40px;
padding-bottom: 20px;
padding-left: 40px;

A négy sort cseréld egyetlen rövidített megadásra:

padding: 20px 40px;
MegadásSorrend / jelentés
20pxMind a négy oldal.
20px 40pxFent-lent; bal-jobb.
10px 20px 30pxFent; bal-jobb; lent.
10px 20px 30px 40pxFent; jobb; lent; bal (óramutató járása szerint).

A shorthand minden oldalt beállít. Ne hagyj utána véletlenül egy régi, oldalankénti értéket, amely módosítja az eredményt.

3. DevTools: mitől ekkora a térköz?

  1. Jobb kattintás a fejlécen → Vizsgálat / Inspect.
  2. Az Elements panelen a header.main-header elemet válaszd ki.
  3. A Styles vagy Computed panel dobozmodell-ábráján keresd a content, padding, border és margin rétegeket.
  4. Ellenőrizd: fent-lent 20, bal-jobb 40 px padding.
  5. Válaszd ki külön a fejléc h1 elemét: ennek saját margója is lehet. A Styles panelen keresd a böngésző szabályait (user agent stylesheet).
A kiemelés színei böngészőnként eltérhetnek; az ábra feliratait és számait olvasd. A DevToolsban végzett módosításokat a CSS-fájlba is írd be, mert az oldal újratöltésekor elveszhetnek.

4. Margin és az utolsó listaelem

Margin = külső térköz. A margin: 10px; minden oldalra adna margót. Most csak a listaelemek alá szeretnénk 10 px-t. A meglévő li szabályba írd:

li {
  margin-bottom: 10px;
}

li:last-child {
  margin-bottom: 0;
}

A li:last-child azt a listaelemet választja ki, amely a szülője utolsó gyermekeleme. A gyakorló listákban az utolsó gyermek is li, így csak az elemek között marad margó. A nulla hosszértékhez nem kell mértékegység; a 0px is érvényes.

Vizsgálj meg egy köztes és egy utolsó listaelemet: a margin-bottom értéke 10 px, illetve 0 legyen. Ez a listaelem margóját törli; a lista saját margója még megmaradhat.

5. A böngésző alapértelmezett térközei

A böngésző a body, címsorok, bekezdések és listák számára is adhat alapértelmezett margót; a listáknál belső térközt, például behúzást is. A pontos értékeket DevToolsban nézd meg.

body {
  margin: 0;
  padding: 0;
}

Próbáld ki: a body külső térköze eltűnik, de a címsorok és listák saját térközei megmaradnak. A margin és a padding alapértelmezésben nem öröklődik. A body beállítása ezért nem reseteli a gyermekeket.

6. Globális reset és specifikusság

A saját gyakorlóoldal style.css fájljának elejére kerüljön:

* {
  margin: 0;
  padding: 0;
}

Az univerzális szelektor minden elemet közvetlenül kijelöl. Ez egy egyszerű térköz-reset: nem az összes böngészőstílust törli. Ezután tudatosan visszaadjuk a szükséges térközöket.

A resetet a gyakorlóoldalba írd, ne ennek a Bootstrap-alapú tananyagoldalnak a stílusai közé!

Azonos eredetű, fontosságú és kaszkádrétegű szabályok között a specifikusabb szelektor nyer:

  • *: (0, 0, 0)
  • li: (0, 0, 1)
  • .main-header: (0, 1, 0)
  • li:last-child: (0, 1, 1)

A fejléc paddingje és a listaelemek margója ezért megmarad a reset mellett. Ez közvetlen kijelölés, nem öröklődés. Azonos specifikusságnál a későbbi szabály dönt. DevToolsban a felülírt deklarációt áthúzva látod.

A listák behúzása is eltűnik. A videó példáját követve az ul, ol szabályban margin-left: 50px; értéket adunk vissza, hogy a jelölőknek legyen helyük. Másik megoldás lehetne a bal padding visszaadása; most a margós változatot használjuk.

7. Az aside paddingje: 50px 0

A kapcsolódó bejegyzések dobozának háttérszíne és szegélye van. Belső térközzel távolítjuk el a tartalmat a felső és alsó kerettől. Először külön állítsd be:

aside {
  padding-top: 50px;
  padding-bottom: 50px;
}

A reset miatt az oldalsó padding nulla. A két sort ezután cseréld le:

aside {
  padding: 50px 0;
}

Fent-lent 50 px, bal-jobb nulla. A teljes oldalankénti megadás megmaradó háttér- és keretszabályait ne töröld. Az oldalsó térközt egy későbbi lépésben tovább alakíthatjuk.

8. A teljes oldal térközeinek kialakítása

A nagyobb befoglaló elemek szabályait érdemes a CSS elején, a body után tartani: fő fejléc, navigáció, cikk, aside. Ez áttekinthetőségi szokás; a forrássorrend azonos specifikusságú ütközéseknél továbbra is számít.

A fő fejléc és a cikk alá 60 px-t adunk. A cikken belüli fejléc kapjon class="post-header" attribútumot: ez a címet, a szerző adatait és a fő képet fogja össze. A külső fejléc marad main-header.

.main-header { margin-bottom: 60px; }
article { margin-bottom: 60px; }
.post-header { margin-bottom: 40px; }
h2 { margin-bottom: 30px; }
p { margin-bottom: 15px; }
ul, ol {
  margin-left: 50px;
  margin-bottom: 20px;
}
h3 {
  margin-top: 40px;
  margin-bottom: 20px;
}

A listák bal margója helyet hagy a számoknak és felsorolásjeleknek, amelyek a reset után az oldal szélén kívülre kerülhettek. A listák alsó margója a következő elemtől választja el őket, míg a li margója az egyes listaelemeket választja el egymástól.

Függőleges térközöknél következetesen használj például alsó margót. A h3 felső margója itt szándékos kivétel a következő kísérlethez. A példában szereplő pixelszámok tervezési döntések; később egységes térközrendszert is használhatunk.

9. Függőleges margók összevonása (margin collapsing)

A gyakorló cikkben egy bekezdés után h3 címsor következik. A bekezdés alsó margója 15 px, a h3 felső margója 40 px. A normál blokkfolyamban ezek a szomszédos függőleges margók összevonódnak: a távolság 40 px, nem 55 px.

p { margin-bottom: 15px; }
h3 { margin-top: 40px; }
p alsó margóh3 felső margóTényleges térköz
15 px40 px40 px
40 px40 px40 px, nem 80
100 px40 px100 px, nem 140
DevToolsban válaszd ki külön a p és h3 elemet. Mindkettő saját margóértéke látható, mégis közös térközt alkotnak. Próbáld ki mindhárom sort, majd állítsd vissza a bekezdés alsó margóját 15 px-re.

A nagyobb érték szabálya itt két pozitív margóra igaz. Az összevonás nem minden elrendezésben történik meg: például flex- és grid-elemek margói nem vonódnak így össze, és a vízszintes margók sem. Negatív margóknál más a számítás. Szülő és gyermek, illetve üres blokkok margói is összevonódhatnak bizonyos feltételekkel; ebben az órában a szomszédos blokkok példáját vizsgáljuk.

10. Szélesség beállítása: width

Az aside később oldalsáv lehet, ezért most a teljes oldalnál keskenyebbre állítjuk:

aside {
  width: 500px;
}

A meglévő aside szabályba írd, a paddinget, háttérszínt és szegélyeket megtartva. Alapértelmezett content-box méretezésben az 500 px a tartalmi szélesség. Itt nincs oldalsó padding és oldalsó keret, ezért a doboz kerettel együtt mért szélessége is 500 px. A fix méret keskeny ablakban túlnyúlhat a rendelkezésre álló helyen.

11. Magasság és a dobozmodell: height

Ideiglenesen add a fő fejléchez:

.main-header {
  padding: 20px 40px;
  height: 80px;
}

DevToolsban a fejléc egészét válaszd ki, ne egy benne lévő linket. A tartalmi magasság 80 px, a felső és alsó padding 20–20 px. Felső és alsó keret nélkül a teljes dobozmagasság 80 + 20 + 20 = 120 px. A margin ezen kívül van.

A height nem igazítja függőlegesen középre a tartalmat. Egyenlő felső és alsó padding mellett, automatikus magasságnál kiegyensúlyozott térköz látszhat; a rögzített magasság viszont további helyet hagyhat alul, vagy túlcsordulhat a tartalom.

A kísérlet után töröld vagy kommentáld ki a height: 80px; sort. A kész oldalon a fejléc magasságát a tartalom határozza meg. Később a border-box méretezést és a függőleges igazítást is megismerjük.

12. Képméretezés és az eredeti képarány

A cikk fő képe kapjon class="post-img" attribútumot. Figyelj rá, hogy a nagy cikkképet jelöld ki, ne a szerző portréját! A kezdő HTML-ben a fő képen width="500" height="200" szerepel.

<img class="post-img" src="img/post-img.jpg"
     alt="HTML-kód egy képernyőn" width="500" height="200">

Először csak a CSS-szélességet állítsd át:

.post-img {
  width: 800px;
}

A CSS-szélesség felülírja a HTML width attribútumából származó méretet, de a rögzített 200 px magasság megmarad. A kép torzulhat. A másik méretet automatikusra állítva visszaáll az eredeti képarány:

.post-img {
  width: 800px;
  height: auto;
}

Próbálj ki 300 px szélességet is: a magasság vele arányosan változik. Ha a másik méretet sem HTML-attribútum, sem CSS-szabály nem rögzíti, akkor az alapértelmezett auto érték miatt rendszerint külön deklaráció nélkül is követi a kép eredeti arányát. A height: auto; itt tudatosan felülírja a meglévő magasságot. Gyakori, hogy a megjelenítési méretet CSS-ben szabályozzuk; a HTML méretattribútumoknak ettől még lehet szerepük.

13. Százalékos szélesség: 100% és 50%

.post-img {
  width: 100%;
  height: auto;
}

A mi normál elrendezésünkben a százalékos szélesség a befoglaló blokk tartalmi szélességéhez viszonyul. A fő kép a header.post-header belsejében van: 100%-nál annak teljes rendelkezésre álló tartalmi szélességét kitölti.

Méretezd át az ablakot: a kép a szülő szélességével együtt változik. Próbáld ki az 50%-ot: a szülő tartalmi szélességének felét tölti ki. Végül állítsd vissza 100%-ra.

A százalék nem feltétlenül a teljes böngészőablak százaléka. Ha a szülő szélessége később fix lesz, az ablak átméretezése önmagában nem változtatja meg ezt a kép szélességét. A százalékos méretezés a reszponzív oldalak egyik alapja, de nem tesz automatikusan minden elemet reszponzívvá.

14. Önálló gyakorlati feladat

  1. A kezdőoldalon jelöld ki külön a fő fejlécet, a cikk fejlécét és a fő képet a main-header, post-header és post-img osztályokkal.
  2. Helyezd a resetet a CSS elejére. A fő fejléc paddingje legyen 20px 40px, az aside-é 50px 0.
  3. A fő fejléc és a cikk alá 60 px, a cikk fejléce alá 40 px margó kerüljön.
  4. A h2 alá 30 px; a h3 fölé 40 px és alá 20 px; a bekezdések alá 15 px margót állíts be.
  5. A listák bal margója 50 px, alsó margója 20 px legyen. A li alá 10 px kerüljön, az utolsó alá nulla.
  6. Vizsgáld meg a 15/40, 40/40 és 100/40 px margópárokat, majd állítsd vissza a 15/40 px-t.
  7. Az aside tartalmi szélessége legyen 500 px.
  8. Próbáld ki a fő fejléc 80 px-es magasságát, ellenőrizd a 120 px dobozmagasságot, majd kapcsold ki a height deklarációt.
  9. A fő képen először próbálj ki 800 px szélességet rögzített HTML-magassággal, majd javítsd az arányt height: auto segítségével. Próbáld ki a 300 px-t is.
  10. Teszteld a kép 100% és 50% szélességét ablakátméretezés mellett. A kész megoldásban 100% és height: auto maradjon.
  11. Mentsd a fájlokat, frissíts, és ellenőrizd a dobozmodellt, a listajelölőket és a kép torzulásmentességét.

Mini kihívás

Írj egyetlen padding deklarációt 10 px felső, 20 px jobb, 30 px alsó és 40 px bal értékkel! Mit változtatna, ha margin lenne helyette?

Teljes CSS-mintamegoldás
/* Térköz-reset: minden elemet közvetlenül kijelöl */
* { margin: 0; padding: 0; }
body { color: #444; font-family: sans-serif; }
/* A nagyobb befoglaló elemek szabályai */
.main-header {
  background-color: #f7f7f7;
  padding: 20px 40px;
  margin-bottom: 60px;
  /* height: 80px; csak az órai kísérlethez */
}
nav { font-size: 18px; }
article { margin-bottom: 60px; }
.post-header { margin-bottom: 40px; }
aside {
  background-color: #f7f7f7;
  border-top: 5px solid #1098ad;
  border-bottom: 5px solid #1098ad;
  padding: 50px 0;
  width: 500px;
}
h1, h2, h3, h4 { color: #1098ad; }
h2 { margin-bottom: 30px; }
h3 { margin-top: 40px; margin-bottom: 20px; }
p { margin-bottom: 15px; }
ul, ol { margin-left: 50px; margin-bottom: 20px; }
li { margin-bottom: 10px; }
li:last-child { margin-bottom: 0; }
.post-img { width: 100%; height: auto; }

A mini kihívás: padding: 10px 20px 30px 40px;. A padding belül, a margin kívül hoz létre helyet.

15. Ellenőrző kérdések

  1. Mit jelent a padding: 20px 40px?
  2. Miért nem elég a body margóját nullázni?
  3. Miért marad meg a fejléc paddingje a reset után?
  4. Mit jelöl ki a li:last-child?
  5. Hol ellenőrzöd a térközök eredetét?
  6. Mekkora térköz lesz a példában 15 és 40 px találkozásakor?
  7. Miért lesz 120 px a fejléc magassága?
  8. Középre igazítja-e a height a szöveget?
  9. Mire való a height: auto a képen?
  10. Mihez viszonyul itt a kép 50%-os szélessége?
  11. Mi marad a kész megoldásban a kísérletekből?
Válaszok
  1. Fent-lent 20 px, bal-jobb 40 px.
  2. A gyermekek saját margói megmaradnak; a margin nem öröklődik alapértelmezésben.
  3. Az osztályszelektor specifikusabb az univerzális szelektornál.
  4. Azt a li elemet, amely a szülője utolsó gyermeke.
  5. Az adott elem Styles / Computed paneljén és dobozmodell-ábráján.
  6. 40 px: a pozitív függőleges margók összevonódnak.
  7. 80 px tartalom + 20 px felső + 20 px alsó padding, keret nélkül.
  8. Nem, csak a magasságot szabályozza.
  9. A rögzített magasságot felülírva lehetővé teszi az eredeti képarány követését.
  10. A befoglaló blokk tartalmi szélességéhez.
  11. 500 px-es aside, automatikus fejlécmagasság, 100% széles kép height: auto mellett.
