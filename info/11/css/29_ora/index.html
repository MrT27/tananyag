11. évfolyam Közlekedési projekt 29. óra

Az első valódi töréspont

A Közlekedési magazin fix, 1200 px-es oldalából elkészítjük a kisebb laptopokon is használható változatot.

Jonas-alap:131–132. videó releváns részei – viewport, külön CSS-fájl, em és kisebb laptopos töréspont

Az óra célja

  • A viewport metaelem szerepének megértése.
  • Külön queries.css fájl létrehozása és bekötése.
  • A pixelben meghatározott töréspont átváltása em-re.
  • Az oldal vizsgálata a töréspont teljes tartományában.
  • A fő Grid, a térközök, a navigáció és a címsor módosítása.
Kezdőcsomag letöltéseMegoldás letöltése

1. A kiinduló probléma

.container {
  width: 1200px;
  grid-template-columns: 1fr 300px;
  column-gap: 75px;
}

A fix 1200 px széles konténer keskenyebb böngészőben nem tud összemenni. A tartalom kilóg, és vízszintes görgetés jelenik meg. Az oldalsáv és a 75 px-es oszlopköz is túl sok helyet foglal.

Nyisd meg a kezdőoldalt Responsive módban! Indulj 1400 px-ről, majd lassan szűkítsd 1100 px-ig. Jegyezd fel, mikor jelenik meg a vízszintes görgetés.

2. A viewport metaelem ellenőrzése

<meta name="viewport"
      content="width=device-width, initial-scale=1.0">

A width=device-width azt kéri, hogy a CSS-nézetablak szélessége igazodjon az eszköz szélességéhez. Az initial-scale=1.0 kezdeti 100%-os nagyítást ad.

A sor már szerepel a projektben. Most nem hozzáadjuk, hanem felismerjük és megértjük. Fizikai mobileszközön nélküle a reszponzív oldal nem a várt módon jelenhet meg.

3. Külön queries.css fájl

A normál megjelenés marad a style.css fájlban. A media queryket külön fájlban gyűjtjük:

<link rel="stylesheet" href="style.css">
<link rel="stylesheet" href="queries.css">

A sorrend fontos: a queries.css később töltődik be, így azonos erősségű szelektorokkal felülírhatja az alapbeállításokat.

Több CSS-fájl használata nem kötelező. Ennél a projektnél azért hasznos, mert jól elkülönülnek az alapstílusok és a reszponzív módosítások.

4. A töréspont átváltása em-re

Az első töréspontot 1200 px környékén választjuk. Media queryben a számításhoz 16 px-es böngésző-alapmérettel dolgozunk:

1200 ÷ 16 = 75

@media (max-width: 75em) {
  /* 1200 px-en és alatta */
}
A media queryben az em számítása nem a projekt esetleges html betűméretéből indul. Itt 75em normál beállítás mellett körülbelül 1200 px.

5. A konténer és a fő Grid javítása

@media (max-width: 75em) {
  .container {
    width: 94%;
    grid-template-columns: 1fr 260px;
    column-gap: 40px;
    row-gap: 40px;
  }
}
  • A százalékos szélesség engedi a konténert összemenni.
  • A 300 px-es oldalsáv 260 px-re csökken.
  • A 75 px-es oszlopköz 40 px-re csökken.
  • A sorköz is kisebb lesz.
Ezen a törésponton még nem bontjuk egy oszlopra az oldalt. A cikk és az oldalsáv továbbra is egymás mellett marad.

6. Finomhangolás ugyanabban a media queryben

@media (max-width: 75em) {
  .main-header {
    padding: 20px 30px;
  }

  nav a:link,
  nav a:visited {
    margin-right: 16px;
  }

  h2 {
    font-size: 34px;
  }

  aside {
    padding: 35px 20px;
  }
}

Nem minden elemet méretezünk át. Csak azokat módosítjuk, amelyek ezen a tartományon már túl sok helyet foglalnak.

7. Ellenőrzés a teljes tartományban

  1. Állítsd a Responsive módot pontosan 1200 px-re.
  2. Ellenőrizd, hogy a media query érvényes.
  3. Próbáld ki 1201 px-en: a media query kapcsoljon ki.
  4. Vizsgáld meg az oldalt 1150, 1050 és 950 px-en is.
  5. Figyeld a navigációt, a címsort, a táblázatot és az oldalsávot.
  6. Ne adj új breakpointot minden apró esztétikai eltéréshez.
Az óra végállapota: az oldal kisebb laptopon már nem lóg ki, de tableten még szándékosan szűkös. Ezt a következő töréspont oldja meg.

8. Önálló feladat

  1. Hozd létre a queries.css fájlt.
  2. Kösd be a style.css után.
  3. Írd meg a 75em-es media queryt.
  4. Alakítsd rugalmasra a konténert.
  5. Csökkentsd az oldalsávot, a réseket, a navigáció margóját, a főcím méretét és az aside paddingjét.
  6. DevToolsban ellenőrizd 1200, 1201, 1050 és 950 px-en.

9. Ellenőrző kérdések

  1. Miért fontos a viewport metaelem?
  2. Miért töltjük be a queries.css fájlt a style.css után?
  3. Hogyan lesz 1200 px-ből 75em?
  4. Miért okozott problémát a fix 1200 px-es szélesség?
  5. Miért nem tesszük még egyoszlopossá a fő Gridet?
  6. Miért kell a breakpoint alatti teljes tartományt ellenőrizni?
Válaszok
  1. A mobileszköz CSS-nézetablakát az eszköz szélességéhez igazítja.
  2. Így az azonos erősségű reszponzív szabályok később felülírhatják az alapstílusokat.
  3. 1200-at elosztjuk 16-tal.
  4. Nem tudott a rendelkezésre álló helynél keskenyebbre zsugorodni.
  5. Ezen a szélességen még használható a kéthasábos elrendezés.
  6. Mert a media query nem csak egyetlen pixelszélességen működik.

Mit vigyél el ebből az órából?

  • A viewport metaelem a fizikai mobilnézet alapfeltétele.
  • A reszponzív szabályok külön CSS-fájlban is tarthatók.
  • A media query töréspontját em-ben adjuk meg.
  • A breakpointnál csak a problémás tulajdonságokat írjuk felül.
  • Egy media query teljes szélességtartományban működik.
